First-time setup
  1. In Airtable, create a table named Inventory in your base. Use the field list in Show Airtable schema below to create the columns, matching names exactly.
  2. Create a personal access token at airtable.com/create/tokens with scopes data.records:read and data.records:write, granted to this base.
  3. Paste the token above and press Save. It is kept in this browser's localStorage only. It is never committed to the repo and never leaves your machine except to call Airtable directly.
  4. Set your base ID below. You can find it in the Airtable API docs URL for your base (it starts with app).

Unlist from everywhere The missing half of crosslisting. When something sells on one marketplace it has to come down from the other six fast, or the same prop gets sold twice and one buyer gets refunded and annoyed. Needs: a per-platform listing URL and status stored on each record, a single Mark sold action that walks the rest, and end-of-listing API calls where one exists (eBay only today) with a checklist for the rest. Until this exists, treat the platform table above as a to-do list you tick off by hand.
Own inventory Right now every record here is one prop going out to marketplaces. If we start holding real stock we need quantity tracked per item, decremented as things sell across channels, and a first-party shop as the source of truth the marketplaces mirror. The Quantity field is already saved for this, but nothing decrements it yet.
Real posting Only eBay has a self-serve listing API, and it needs a server-side OAuth secret that a static page cannot hold. The commercial crosslisters (Vendoo, List Perfectly) are browser extensions that drive each marketplace's own form in your logged-in session, which is the only approach that reaches Poshmark, Mercari and Facebook Marketplace at all. Worth knowing before anyone plans a SaaS around this.
